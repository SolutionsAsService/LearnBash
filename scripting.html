A first script

A script is a text file of commands. The first line, the shebang, names the interpreter. #!/usr/bin/env bash finds bash on your PATH, which is more portable than hard-coding /bin/bash. Make the file executable with chmod +x and run it with a path, because the current directory is not on PATH.

Arguments arrive as $1, $2 and so on; $0 is the script's name, $# the number of arguments and "$@" all of them, each kept as one word.

Making decisions

if runs a command and branches on its exit status. The usual command is a test: [[ ... ]] in Bash (a keyword, safer with spaces and empty values) or [ ... ] in any POSIX shell. Compare numbers with -eq, -lt, -gt and strings with = and != (POSIX). == also works inside [[ ]] and in Bash's [ ], but not in dash. File tests include -f (a regular file), -d (a directory) and -e (exists).

case matches a value against patterns and is tidier than a long if chain.

Loops

for repeats over a list, which is often a glob. while repeats while a command succeeds; with read it processes a file line by line. break leaves a loop and continue skips to the next round.

Use read -r so backslashes in the data are not treated as escapes, and IFS= to keep leading spaces.

Functions

A function groups commands under a name. Its arguments are $1, $2, ... inside it. Declare variables with local so they do not leak. A function can return a status with return (0 to 255), but it hands back text by printing it, which the caller captures with $(...).

Define functions before you call them.

Parameter expansion

Bash can edit a variable's value as it expands it, with no external programs. ${var:-default} supplies a default, ${#var} gives the length, ${var#pattern} and ${var##pattern} remove a prefix (shortest and longest match), ${var%pattern} and ${var%%pattern} remove a suffix, and ${var/old/new} substitutes.

These are quicker and safer than calling sed or basename for simple edits.

Arrays

An indexed array holds several values: items=(a b c). Read one with ${items[0]}, all of them with "${items[@]}" (quoted, so each stays one word), and the count with ${#items[@]}. Associative arrays (declare -A) map names to values but need Bash 4 or newer; macOS still ships Bash 3.2, which has neither the feature nor several others used on this site.

Failing safely

By default a script carries on after an error. Three settings change that: set -e exits when a command fails, set -u treats an unset variable as an error, and set -o pipefail makes a pipeline fail if any stage fails (otherwise only the last stage counts). Together, set -euo pipefail at the top is a common safety net.

It is not a cure-all: set -e does not exit for a failure inside a condition (an if or while test, or the left side of && and ||), and it can surprise you. Check the cases you care about explicitly, and run ShellCheck over your scripts.

A worked example: which pages are missing?

Log files record one event per line, and a pipeline of small tools answers questions about them without a database. The sample log in this sandbox has 40 requests. Which pages returned status 404 (not found), and how often?

Each stage does one job: awk keeps the path of lines whose ninth field is 404, sort groups equal paths together, uniq -c counts each group, and sort -rn puts the biggest count first.

Safety habits

Quote your variables. Prefer set -euo pipefail while developing. Print a command before you run something destructive (echo rm ... first). Never run a script you have not read, especially a one-liner that pipes a download into a shell. Use mktemp for temporary files instead of fixed names. Keep secrets out of command lines, where other users can see them in the process list.

ShellCheck (shellcheck.net) catches many of these mistakes automatically and explains each warning.
