File descriptors and redirection

Every process has numbered streams: 0 is standard input, 1 standard output, 2 standard error. N> redirects stream N, and 2>&1 means 'send stream 2 to wherever stream 1 now goes'. Order matters: redirections are processed left to right.

&> file sends both streams to a file in Bash. /dev/null discards anything written to it.

Here-documents and here-strings

A here-document feeds several lines to a command: command <<'EOF' ... EOF. Quoting the delimiter ('EOF') stops the shell from expanding variables inside; leave it unquoted to expand them. A here-string, <<< word, feeds one string.

Use <<- with tab indentation to strip leading tabs.

Process substitution and command grouping

<(command) makes a command's output look like a file, so you can compare or join two results without temporary files. ( ... ) runs commands in a subshell, a copy of the shell whose changes (such as cd or variable assignments) are discarded afterwards. { ...; } groups commands in the current shell, handy for redirecting all their output at once.

Process substitution is a Bash feature; it is not part of POSIX sh.

Brace expansion, arithmetic and substitution

Brace expansion builds lists before anything else happens: {a,b,c} and {1..5}. $(( expression )) does integer arithmetic (no decimals). $(command) captures output, and unlike the older backticks it nests.

Bash 4 added case conversion: ${var^^} for upper case and ${var,,} for lower.

Background jobs

End a command with & to run it in the background. wait pauses until background jobs finish. $! holds the last background job's process ID. Interactive shells also offer jobs, fg and bg, and Ctrl-Z to suspend a program.

A background job still writes to your terminal and is stopped when the terminal closes, unless you use nohup or a terminal multiplexer.

Cleaning up with trap

trap 'commands' SIGNAL runs commands when the shell receives a signal or an event. The EXIT pseudo-signal fires whenever the script ends, however it ends, which makes it the right place to delete temporary files. Traps for INT (Ctrl-C) and TERM let a script clean up when interrupted.

Debugging

bash -x script.sh, or set -x inside a script, prints each command after expansion, prefixed with +, so you can see exactly what Bash ran. bash -n script.sh checks syntax without running anything. ShellCheck finds quoting mistakes, unused variables and portability problems before you run the script.

Add a PS4 prefix with the line number for long scripts: PS4='+ line $LINENO: '.

Bash versus POSIX sh, GNU versus BSD

Not every system is the same. #!/bin/sh may be a smaller shell (dash on Debian and Ubuntu) that lacks [[ ]], arrays, process substitution and more. macOS ships Bash 3.2 and BSD versions of tools: sed -i needs an argument (sed -i ''), date -d does not exist, and some grep and ls flags differ. If a script must run everywhere, write for POSIX sh and test with a strict shell; if it can require Bash, say so in the shebang and in the README.
